# How to Run — Python VRN Processing Scripts

This guide explains the **7–8 Python scripts** in `Next Processing/python scripts csv`: what each one does and how to run them on your final VRN CSV.

---

## Before You Run Anything

Per `Steps.txt` and `Project Overview.txt`, these scripts are **step 5** — they run **after** Power BI / preprocessing:

1. Convert VRN + lifecycle files to CSV
2. Normalize column values (MOP, TC Class, Lane No, Description, etc.)
3. Append lifecycle columns `{Date & Time, Veh Reg No., MOP, Lane No}` into the VRN file
4. Create a merged key from `{Veh Reg No., Date & Time, MOP}` and remove duplicates

Your **input** to the Python pipeline is that deduplicated VRN CSV.

### Required Input Columns

From `data_processing.py`, the CSV must have at least:

| Column | Used for |
|--------|----------|
| `Veh Reg No.` | Vehicle identification |
| `Date & Time` | Timestamp parsing & time-gap logic |
| `MOP` | Payment mode filtering & `MOP Final` derivation |
| `Lane No` | Side 1 vs Side 2 mapping (L1–L8 vs L9–L16) |
| `Description` | Exempt reason breakdown (RF3 pivot) |
| `TC Class` | Commercial vs Non-Commercial |

### Configure Paths First

Edit `config.py` before running:

```python
file_path = r"E:/Mihir NHIT Q4/Mudipar/exempt files/nov-25/nov-vrn.csv"
base_output_path = r"E:/Mihir NHIT Q4/Mudipar/exempt files/nov-25"
plaza_name = "MUDIPAR"
file_name = "nov-25.xlsx"
```

- **`file_path`** → your final VRN CSV
- **`base_output_path`** → folder where all intermediate/final Excel files are written
- **`plaza_name`** → must match an entry in `codes_dump.json` (for Local/Non-Local logic)
- **`file_name`** → final output filename (e.g. `nov-25.xlsx`)

### Extra Files Needed (Not Generated by the Scripts)

| File | Used by | Purpose |
|------|---------|---------|
| `codes_dump.json` | `combined_with_rf3.py` | Plaza → local vehicle registration prefix (e.g. MUDIPAR → CG10) |
| `mudi_mp.xlsx` | `Date_validity_check.py` | MP working file with `Chassis/ Vehicle No`, `Start Date`, `End Date` |
| `Bjp_LT.xlsx` | `Date_validity_check_LT.py` | LT working file (same column structure) |

`dump_codes.py` is a one-time utility to rebuild `codes_dump.json` from `local code - plaza wise.xlsx` — not part of the normal monthly run.

## What Each Script Does (In Order)

### Support Modules (Not Real Processing Steps)

| File | Role |
|------|------|
| **`config.py`** | Central paths and plaza settings — edit this, don't "run" it for processing |
| **`data_processing.py`** | Shared loader: reads CSV, filters bad MOPs, creates `MOP Final` (ETC vs EXEMPT), maps lanes to Side 1/2 |

These are imported by the other scripts. The orchestrator lists them, but running them alone does nothing useful.

---

### Step 1 — `main_script.py` — Exempt Exception Detection

**Input:** VRN CSV (via `config.py`)  
**Output:** `updated_new_Combined_Side_Results.xlsx`

What it does:

- Loads and preprocesses the VRN data
- Splits work by **Side 1** (lanes L1–L8) and **Side 2** (L9–L16)
- For vehicles that had at least one EXEMPT transaction, looks at each EXEMPT row in chronological order
- Compares with previous/next transactions for the same vehicle
- Labels each EXEMPT row as **Exception** or **Non Exception 1/2/3** based on time gaps and adjacent MOP types (e.g. another EXEMPT within 15 min, or ETC/Cash within 16 hours)

---

### Step 2 — `RF3_condition.py` — RF3 Pivot / TRI Flags

**Input:** Same VRN CSV  
**Output:**

- `RF3 Pivot.xlsx` — full pivot by exempt description
- `rf3_1.xlsx` — vehicles where TRI 2 & 3 = `00`
- `rf3_2.xlsx` — TRI 1, TRI 2, TRI 3 per vehicle

What it does:

- Filters EXEMPT transactions only
- Groups by vehicle and counts exempt descriptions (AMBULANCE, GOVT, LOCAL, etc.)
- Computes **TRI 1** (single exempt trip), **TRI 2** (all trips same description), **TRI 3** (count of ETC trips)
- Pivots description counts into columns

---

### Step 3 — `combined_with_rf3.py` — Merge Exception + RF3 + Trip Rules

**Input:**

- `updated_new_Combined_Side_Results.xlsx` (from step 1)
- `rf3_1.xlsx`, `rf3_2.xlsx` (from step 2)
- Original VRN CSV

**Output:** `combined_with_rf3.xlsx` (sheet: `Combined with RF 3`)

What it adds:

- TRI columns from RF3
- **Local/Non Local** from vehicle reg prefix vs plaza code in `codes_dump.json`
- **C/NC** (Commercial / Non Commercial) from `TC Class`
- **LNC/NLNC/LC/NLC** combined label
- **Trip Rules** — total trip count including VIOLATION, FLEET, CONVEY, RUNTHROUGH rows
- **Exempt txn** = Trip Rules − TRI 3
- **Trip Group** = `0-5` or `>5`

---

### Step 4 — `Date_validity_check.py` — MP Date Validity

**Input:**

- `combined_with_rf3.xlsx`
- `mudi_mp.xlsx` (working file)

**Output:** `MP Output.xlsx`

What it does:

- Joins each transaction to the MP working file on `Veh Reg No.` = `Chassis/ Vehicle No`
- Checks if transaction date falls between `Start Date` and `End Date`
- Adds column **Date Validity Check MP** → `Valid` or `Not Valid`

---

### Step 5 (Optional) — `Date_validity_check_LT.py` — LT Date Validity

**Input:**

- `MP Output.xlsx`
- `Bjp_LT.xlsx`

**Output:** `LT_output.xlsx`

Same logic as step 4, but adds **Date Validity Check LT**. This is **commented out** in the batch runner, so it's the "8th" script when your plaza needs LT validation.

---

### Step 6 — `Return_Journey_Logic.py` — First vs Return Journey

**Input:** `MP Output.xlsx`  
**Output:** `{file_name}.xlsx` from config (e.g. `nov-25.xlsx`) with two sheets:

- `Combined with RF 3` — all prior columns + **Journey Type** (`First Journey` / `Return Journey`)
- `RF3 Pivot` — copied from `RF3 Pivot.xlsx`

Journey logic:

- Sort by vehicle + datetime
- If same vehicle, within 24 hours, and lane **side changes** (Side 1 ↔ Side 2) → **Return Journey**
- Otherwise → **First Journey**

## How to Run

### Option A — Run All Scripts in Sequence (Recommended)

From the scripts folder:

```powershell
cd "C:\Divyesh\NHIT_File_process\Next Processing\python scripts csv"
python "import subprocess.py"
```

The runner executes in this order:

1. `config.py`
2. `data_processing.py`
3. `main_script.py`
4. `RF3_condition.py`
5. `combined_with_rf3.py`
6. `Date_validity_check.py`
7. `Return_Journey_Logic.py`

(`Date_validity_check_LT.py` is commented out by default.)

To include LT validation, uncomment `Date_validity_check_LT.py` and run it **after** `Date_validity_check.py` but **before** `Return_Journey_Logic.py`. Note: Return Journey reads `MP Output.xlsx`, not `LT_output.xlsx` — if you use LT, you may need to point Return Journey at `LT_output.xlsx` instead.

### Option B — Run Manually One by One

```powershell
cd "C:\Divyesh\NHIT_File_process\Next Processing\python scripts csv"

python main_script.py
python RF3_condition.py
python combined_with_rf3.py
python Date_validity_check.py
python Date_validity_check_LT.py          # optional
python Return_Journey_Logic.py
```

Order matters — each step reads outputs from the previous one.

### Python Dependencies

You'll need: `pandas`, `openpyxl`, `numpy` (for `combined_with_rf3.py`).

```powershell
pip install pandas openpyxl numpy
```

## Things to Watch Out For

1. **`Return_Journey_Logic.py` has a syntax error** on line 11 — it's missing a `+` between `'/'` and `"MP Output.xlsx"`. As written it won't run until that's fixed.

2. **`config.py` paths** may still point to old locations (e.g. `E:/Mihir NHIT Q4/Mudipar/...`) — update them to your actual VRN CSV and output folder.

3. **Working file names are plaza-specific** — `mudi_mp.xlsx` looks like it was written for MUDIPAR; your plaza may need differently named MP/LT files with the same column structure.

4. **`main_script.py` uses `'Cash'` and `'Exempt'`** in exception logic, but `data_processing.py` normalizes to `'ETC'` and `'EXEMPT'` — some Non Exception branches may never trigger unless that casing is aligned.

5. **Large files** — `Steps.txt` notes ~2.5 minutes per 7 lakh rows for CSV conversion; these Python steps on full-month VRN data can also take noticeable time.
